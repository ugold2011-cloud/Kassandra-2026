# KASSANDRA --- SESSION EFFICIENCY CONTROL LAW

## Purpose

Mandatory operating rule for managing Kassandra-2026 work sessions
efficiently and safely.

## RULE 1 --- SESSION START

At the beginning of every new Kassandra-2026 session, read this document
before continuing. Establish the current checkpoint, completed/verified
work, remaining work, and previous PASS results that must not be
repeated without a concrete reason.

## RULE 2 --- HOURLY EFFICIENCY CHECK

At every full hour during an active work session, perform an internal
efficiency review before continuing: 1. Did the previous hour materially
advance the goal? 2. Are tests, commands, screenshots, scans, or
verification steps being repeated unnecessarily? 3. Is there already
sufficient evidence for PASS? 4. Is there a shorter and equally safe
path to the next objective? 5. Is the process wasting the user's time or
usage quota?

## RULE 3 --- MANDATORY CORRECTION

If inefficiency is found, immediately change the process: - Stop
unnecessary repeated checks. - Do not request evidence already
sufficiently established. - Consolidate related checks whenever safe. -
Prefer one decisive diagnostic over many micro-checks. - Keep safety
gates where they protect files, data, or completed work. - Continue by
the shortest safe route toward the objective.

## RULE 4 --- NO TESTING FOR TESTING'S SAKE

Every verification must answer a specific unresolved question. If the
result is already known and no relevant state changed, do not repeat it.

## RULE 5 --- PASS IS PASS

Once a stage has sufficient evidence and is marked PASS, do not reopen
it unless a later change could have affected it, contradictory evidence
appears, or the user explicitly requests a re-check.

## RULE 6 --- PROTECT COMPLETED WORK

Efficiency never justifies reckless changes. Before broad, destructive,
automated, Git, deployment, or cross-file operations, identify exactly
what will change and protect unrelated work.

## RULE 7 --- USER INTERACTION COST

Treat every unnecessary command, screenshot, approval request, and
repeated explanation as a cost. Do not make the user perform steps that
can safely be avoided or combined.

## RULE 8 --- HOURLY CHECK IS INTERNAL

The hourly review normally happens silently. Interrupt the user only if
it causes a meaningful change of plan or the user asks.

## RULE 9 --- SESSION CONTINUITY

Do not restart completed work because a new session began. Continue from
the last verified checkpoint.

## MASTER PRINCIPLE

Shortest safe path to a verified result. Safety without bureaucracy.
Verification without repetition. Progress without wasting time or quota.
